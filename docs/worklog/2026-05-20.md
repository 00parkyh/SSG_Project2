- `담당자` 컬럼은 DB 조회 대신 로그인 세션의 담당자 이름을 화면에 표시한다.

# 수정 이유

- 사용자가 원하는 목록 컬럼은 `실사 ID, 실사 일자, 실사 상태, 창고명, 섹션명, 조정 여부, 담당자`이며, 이 중 `담당자`는 DB가 아니라 로그인 세션 값을 사용하기로 결정했다.
- 기존 목록 렌더링은 상품/수량 중심 10개 컬럼 기준이어서 현재 V2 테이블 헤더와 맞지 않았다.
- 목록 API 호출이 비활성화되어 있어 실사 리스트가 화면에 표시되지 않았다.

# 추가로 해야 할 작업

- 브라우저에서 실사 목록이 7개 컬럼으로 표시되는지 확인한다.
- 다른 사용자로 로그인했을 때 `담당자` 컬럼이 세션 사용자명으로 바뀌는지 확인한다.

### 수정 전 코드

```sql
CREATE TABLE PhysicalInventory (
    pi_id int NOT NULL AUTO_INCREMENT,
    ps_id int NOT NULL,
    pi_date timestamp NOT NULL,
    ...
)
```

```xml
SELECT
    PI.pi_id AS piId,
    P.product_id AS productId,
    ...
FROM PhysicalInventory PI
...
ORDER BY PI.pi_date DESC, PI.pi_id DESC
```

### 수정 후 코드

```sql
CREATE TABLE PhysicalInventory (
    pi_id int NOT NULL AUTO_INCREMENT,
    inventory_batch_id varchar(36) NOT NULL,
    ps_id int NOT NULL,
    ...
)
```

```xml
SELECT
    MIN(PI.pi_id) AS piId,
    PI.inventory_batch_id AS inventoryBatchId,
    DATE_FORMAT(MIN(PI.pi_date), '%Y-%m-%d') AS piDate,
    ...
FROM PhysicalInventory PI
...
GROUP BY PI.inventory_batch_id, W.warehouse_name, S.section_name
```

### 수정 이유

- 기존 구조는 실사 등록 1회가 물품 수만큼 여러 row로 생성되어 실사 리스트와 실사 상세를 안정적으로 구분할 수 없었다.
- `inventory_batch_id`를 추가해 한 번의 실사 등록을 하나의 배치로 묶고, 리스트는 배치 기준 1건, 상세는 배치 기준 품목 목록으로 조회하도록 바꿨다.
- 실제 Docker MySQL의 `PhysicalInventory`에도 동일 컬럼과 인덱스를 추가했다.

### 추가로 해야 할 작업

- 브라우저에서 실사 등록 후 리스트에 배치 기준 1건만 표시되는지 확인한다.
- 리스트 클릭 시 상세 모달에 품목 목록이 표시되는지 확인한다.
- `완료` 상태에서만 품목별 실제 수량과 조정 여부 저장이 되는지 확인한다.
- `./gradlew compileJava` 검증은 현재 wrapper 손상(`org.gradle.wrapper.GradleWrapperMain` 누락)으로 수행하지 못했다.
