## RoleCheckInterceptor 테스트 추가

### 작업 목적
- `RoleCheckInterceptor`의 보수적 fallback 정책과 URL별 권한 규칙이 의도대로 동작하는지 테스트로 고정한다.

### 수정한 파일
- `src/test/java/com/ssg/wms/config/RoleCheckInterceptorTest.java`

### 수정 전 코드
```java
@Test
void allowsAdminAndManagerAccessToStockPath() throws Exception {
    MockHttpServletRequest adminRequest = new MockHttpServletRequest("GET", "/physical-inventory");
    MockHttpSession adminSession = new MockHttpSession();
    adminSession.setAttribute("role", Role.ADMIN);
    adminRequest.setSession(adminSession);

    MockHttpServletRequest managerRequest = new MockHttpServletRequest("GET", "/physical-inventory");
    MockHttpSession managerSession = new MockHttpSession();
    managerSession.setAttribute("role", Role.MANAGER);
    managerRequest.setSession(managerSession);

    assertTrue(interceptor.preHandle(adminRequest, new MockHttpServletResponse(), new Object()));
    assertTrue(interceptor.preHandle(managerRequest, new MockHttpServletResponse(), new Object()));
}
```

### 수정 후 코드
```java
@Test
void allowsAdminAndManagerAccessToProductListPath() throws Exception {
    assertAllowed("/productList/plist", Role.ADMIN);
    assertAllowed("/productList/plist", Role.MANAGER);
}

@Test
void deniesMemberAccessToProductListPath() throws Exception {
    assertForbidden("/productList/plist", Role.MEMBER);
}

@Test
void deniesUnmappedAuthenticatedPathByDefault() throws Exception {
    assertForbidden("/unmapped/path", Role.ADMIN);
    assertForbidden("/unmapped/path", Role.MANAGER);
    assertForbidden("/unmapped/path", Role.MEMBER);
}
```

### 수정 이유
- `/productList/**`는 `ADMIN`, `MANAGER`만 접근해야 한다.
- `/partner/**`는 `ADMIN`만 접근해야 한다.
- `/announcements/**`, `/inquiries/**`, `/api/inquiries/**`는 로그인된 모든 권한이 접근 가능해야 한다.
- 명시되지 않은 URL은 fallback `return false` 정책에 따라 차단되어야 한다.

### 검증
```text

```

### 추가로 해야 할 작업
- 실제 브라우저 테스트 중 새 정상 URL이 403으로 막히면 해당 URL을 권한 정책에 명시한다.

## WebConfig 중복 인터셉터 설정 정리 및 로그인 JSP 오타 수정

### 작업 목적
- 인터셉터 설정을 `servlet-context.xml` 한 곳으로 통일한다.
- 공통 로그인 페이지의 잘못된 JSTL 태그 오타를 수정한다.

### 수정한 파일
- `src/main/java/com/ssg/wms/config/WebConfig.java`
- `src/main/webapp/WEB-INF/views/login.jsp`

### 수정 전 코드
```java
@Log4j2
@Configuration
public class WebConfig implements WebMvcConfigurer {

    @Override
    public void addInterceptors(InterceptorRegistry registry) {
        registry.addInterceptor(new RoleCheckInterceptor("ADMIN"))
                .addPathPatterns("/admin/**", "/dashboard/**", "/sales/**", "/expense/**")
                .excludePathPatterns("/admin/login");

        registry.addInterceptor(new RoleCheckInterceptor("ADMIN", "MANAGER"))
                .addPathPatterns("/stock/**");

        registry.addInterceptor(new RoleCheckInterceptor("ADMIN", "MANAGER", "MEMBER"))
                .addPathPatterns("/**");
    }
}
```

```jsp
<script src="<cm:url value='/resources/assets/vendor/js/menu.js'/>"></script>
```

### 수정 후 코드

    }

### 수정 이유
- `WebConfig`의 이전 인터셉터 등록과 `servlet-context.xml`의 현재 인터셉터 등록이 중복될 수 있었다.
- 현재 권한 정책은 `servlet-context.xml`에 등록된 `RoleCheckInterceptor` 하나에서 처리해야 한다.
- `cm:url`은 정의되지 않은 태그 prefix라 리소스 URL 렌더링이 깨질 수 있다.
