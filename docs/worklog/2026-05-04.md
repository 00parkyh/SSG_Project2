## 수정 이유

- 조정 여부 값이 JSP와 서비스 로직에 흩어져 있으면 상태 추가나 이름 변경 시 수정 지점이 많아짐
- DB는 기존 `VARCHAR` 값을 그대로 유지하면서 백엔드에서만 enum으로 관리하면 스키마 변경 없이 상태값 일관성을 확보할 수 있음
- 서비스의 `"조정 완료"` 문자열 비교를 enum 비교로 바꾸면 오타 위험을 줄일 수 있음

## 수정 후 코드

```javascript
function getLocalDateString() {
    const today = new Date();
    const year = today.getFullYear();
    const month = String(today.getMonth() + 1).padStart(2, '0');
    const day = String(today.getDate()).padStart(2, '0');
    return year + '-' + month + '-' + day;
}

const piDateInput = document.getElementById('piDate');
if (piDateInput) {
    piDateInput.value = getLocalDateString();
}
```

## 수정 이유

- `input type="date"` 의 `valueAsDate` 는 브라우저가 `Date` 객체를 UTC 기준으로 해석하는 경우가 있어 한국 시간대에서는 하루 전 날짜로 보일 수 있음
- 로컬 시간 기준 `yyyy-MM-dd` 문자열을 직접 만들어 넣으면 브라우저와 타임존 차이 없이 현재 날짜가 정확히 표시됨
