## 수정 이유

- `Sales.sales_code`, `Expense.expense_code`는 `NOT NULL`인데 Mapper insert에서 해당 컬럼을 누락해 신규 insert가 실패했다.
- 서비스는 insert 후 최종 관리번호를 update하는 구조이므로, insert 시점에는 임시 관리번호를 넣어 NOT NULL 제약을 만족시켰다.
- Inbound 테스트는 존재하지 않는 `P001` 상품을 사용해 `InboundItem.product_id` FK 제약을 위반했다.
- 프로젝트 더미 데이터에 존재하는 `NK-SS-01` 상품 ID로 테스트 데이터를 맞췄다.

## 수정 후 코드

```java
@Test
public void shouldKeepStockConsistentWhenMovingNikeProductsBetweenWarehouses() {
    long capitalWarehouseId = findWarehouseIdByName("수도권");
    long yeongnamWarehouseId = findWarehouseIdByName("영남");

    cleanupProductStock(yeongnamWarehouseId, ALL_PRODUCTS);

    for (String productId : ALL_PRODUCTS) {
        moveFromExternalSourceToWarehouse("인천항", capitalWarehouseId, productId, 2000, 200);
    }

    for (String productId : TRANSFER_PRODUCTS) {
        moveBetweenWarehouses(capitalWarehouseId, yeongnamWarehouseId, productId, 1000, 100);
    }
}
```

## 수정 이유

- 수도권 통합 의류센터와 영남 스포츠웨어센터 간 재고 이동 후 최종 재고 수량이 맞는지 검증한다.
- 인천항 입고는 1회 최대 200벌 제한을 검증한다.
- 센터 간 이동은 1회 최대 100벌 제한을 검증한다.
- 제한 초과 이동 요청 시 예외가 발생하고 재고가 변하지 않는지 검증한다.
- 테스트는 `@Transactional`로 실행되어 테스트 종료 후 변경 데이터가 롤백된다.
