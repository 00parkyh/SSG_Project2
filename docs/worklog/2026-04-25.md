## 작업 목적

- admin 계정으로 창고관리자 로그인 시 발생하던 500 에러의 원인을 제거
- 창고관리자 로그인 경로에서 MANAGER 권한 계정만 인증되도록 제한

## 수정한 파일

- `src/main/resources/mappers/ManagerMapper.xml`

```java
if (uri.equals("/warehousemanager/login")) return;
```

## 수정 후 코드

```java
if (isManagerLoginRequest(request)) {
    return;
}

if (uri.startsWith("/warehousemanager")) {
    Role role = getSessionRole(session);

    if (role == null) {
        response.sendRedirect("/login");
    } else if (role != Role.MANAGER) {
        response.sendError(HttpServletResponse.SC_FORBIDDEN, "창고관리자 전용 페이지입니다.");
    }
}

private Role getSessionRole(HttpSession session) {
    if (session == null) {
        return null;
    }

    return (Role) session.getAttribute("role");
}

private boolean isManagerLoginRequest(HttpServletRequest request) {
    String uri = request.getRequestURI();
    String method = request.getMethod();

    return uri.equals("/warehousemanager/login")
            || (uri.equals("/warehousemanager") && "POST".equalsIgnoreCase(method));
}
```

```xml

</select>
```

## 수정 이유

- 창고관리자 로그인 폼은 `POST /warehousemanager` 로 요청되는데, 기존 공통 권한 체크는 이 경로를 로그인 예외로 보지 않아 세션이 없는 상태에서 `session.getAttribute("role")` 를 먼저 호출했고 그 결과 500 에러가 발생할 수 있었음
- 창고관리자 로그인 쿼리에 역할 조건이 없어 admin 계정도 조회 대상이 되었기 때문에, 로그인 단계에서 MANAGER 계정만 통과하도록 제한할 필요가 있었음

## 추가로 해야 할 작업

- Gradle wrapper jar(`gradle-wrapper.jar`)를 복구한 뒤 `./gradlew test` 또는 최소 `./gradlew compileJava` 로 빌드 검증 수행
- 브라우저에서 `admin` 계정으로 `/warehousemanager` 로그인 시도 시 500 대신 로그인 실패 또는 권한 거부로 처리되는지 확인
