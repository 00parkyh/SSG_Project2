## 작업 목적

- 재고 실사 목록과 상세 모달에서 `실사 ID`라는 화면 문구를 `대표 실사 번호`로 변경했다.
- DB 변경 없이 현재 목록 SQL의 `MIN(pi_id)` 값을 실사 등록 묶음의 대표 번호로 사용한다는 의미를 화면에 반영했다.

## 수정 이유

- `pi_id`는 실사 상세 row 단위 PK라서 한 번의 실사 등록에 여러 품목이 포함되면 여러 개 증가한다.
- 목록 조회는 `inventory_batch_id`로 묶고 `MIN(PI.pi_id) AS piId`를 대표값으로 내려주고 있으므로, 사용자 화면에서는 `실사 ID`보다 `대표 실사 번호`가 더 정확하다.
- DB 스키마 변경 없이 기존 대표값 표시 방식을 유지했다.

## 작업 목적

- 인증/인가 책임을 `RoleCheckInterceptor` 하나로 모았다.
- 로그인 성공 이후에만 서버 세션이 생성되도록 권한별 로그인 POST 흐름을 수정했다.
- 로그인 페이지 진입만으로 JSP가 세션을 생성하지 않도록 로그인 JSP에 `session="false"`를 적용했다.

## 수정 후 코드

```java
public String postAdminLogin(..., HttpServletRequest request, Model model) {
    Staff staff = adminService.loginCheck(loginId, password);
    ...
    HttpSession session = request.getSession(true);
    session.setAttribute("loginId", loginId);
}
```

```java
public final class GlobalRoleChecker {
    private GlobalRoleChecker() {
    }
}
```

```jsp
<%@ page language="java" contentType="text/html;charset=UTF-8" pageEncoding="UTF-8" session="false" %>
```

## 수정 이유

- `HttpSession`을 로그인 POST 파라미터로 받으면 로그인 실패 전에도 세션이 생성될 수 있다.
- 로그인 성공 이후에만 `request.getSession(true)`를 호출하도록 바꿔 빈 세션 생성을 줄였다.
- 기존 `ControllerAdvice` 기반 권한 체크와 인터셉터 권한 체크가 중복되어 세션 만료 시 동작이 꼬일 수 있었다.
- `RoleCheckInterceptor`에서 공개 경로, 세션 만료, 잘못된 role, 경로별 권한 검사를 한 번에 처리하도록 정리했다.
