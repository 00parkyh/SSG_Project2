### `src/main/resources/db_sql/finalDB.sql`
```sql
CREATE TRIGGER `trg_dispatch_bi`
BEFORE INSERT ON `dispatch`
FOR EACH ROW
BEGIN
    IF NEW.warehouse_id IS NOT NULL THEN
        SET NEW.warehouseId = NEW.warehouse_id;
    ELSEIF NEW.warehouseId IS NOT NULL THEN
        SET NEW.warehouse_id = NEW.warehouseId;
    END IF;
END
```

## 수정 이유
- `member.business_number`가 mapper에서 필수로 사용되는데 기존 스키마에 누락되어 있었다.
- `dispatch`는 mapper에서 `warehouseId`와 `warehouse_id`, `driverName`과 `driver_name`, `loadedBOX`와 `loaded_box`를 혼용하고 있었다.
- `sales`, `expense`는 mapper가 `sales_code`, `expense_code`, `status`를 사용하지만 일부 DDL 버전에서는 기본 저장 로직과 충돌하는 `NOT NULL` 정의가 있었다.
- `partner_contract.status`, `driver` 테이블, `product_stock.las_updatedate` 같은 항목도 mapper 기준으로 보완이 필요했다.

## 추가로 해야 할 작업
- `DispatchMapper.xml`의 `updateDispatchInformation` 구문은 `dispatchStatus` 뒤에 콤마가 없어, 스키마와 별개로 실행 시 SQL 문법 오류가 날 수 있다.
- 실제 MySQL 인스턴스에 적용 전에는 로컬 DB 백업 후 `finalDB.sql` 기준으로 초기화 검증을 한 번 수행하는 것이 안전하다.

## 수정 이유
- Windows PowerShell은 BOM 없는 UTF-8 Markdown 파일을 기본적으로 CP949로 읽어 한글이 깨질 수 있다.
- Markdown 파일을 UTF-8 BOM으로 통일하고 `.editorconfig`에 저장 규칙을 추가하면 이후 문서 작성 시 같은 문제가 재발할 가능성을 낮출 수 있다.

## 추가로 해야 할 작업
