## 수정 후 코드
```javascript
function initializeAdjustmentStatusOptions() {
    const updateStateCells = document.querySelectorAll('.modal-update-state');
    updateStateCells.forEach(function (select) {
        select.innerHTML = '';
        adjustmentStatuses.forEach(function (status) {
            const option = document.createElement('option');
            option.value = status.value;
            option.textContent = status.label;
            select.appendChild(option);
        });
    });
}
```

## 수정 이유
- `DOMContentLoaded`에서 `initializeAdjustmentStatusOptions()`를 호출하고 있었지만 함수 정의가 없어 `ReferenceError`가 발생했다.
- 그 영향으로 이후 `searchPhysicalInventoryList(1)` 호출이 실행되지 않아 초기 placeholder 문구가 계속 남아 있었다.
- 누락된 함수만 복구해 페이지 초기화 흐름을 정상화했다.

## 수정 후 코드
```sql
INSERT INTO ProductStock (
    warehouse_id,
    section_id,
    inbound_item_id,
    outbound_item_id,
    quantity,
    product_status,
    last_update_date
)
SELECT ...
WHERE ps.ps_id <= 100
  AND seq.n <= 3000;

INSERT INTO ProductStockLog (
    ps_id,
    event_time,
    move_quantity,
    event_type,
    product_status,
    destination
)
SELECT ...
FROM ProductStock ps
JOIN (...) evt
WHERE ps.ps_id > 100;

INSERT INTO PhysicalInventory (
    inventory_batch_id,
    ps_id,
    pi_date,
    pi_state,
    pid_quantity,
    real_quantity,
    different_quantity,
    update_state
)
SELECT ...
FROM ProductStock ps
WHERE ps.ps_id > 100
  AND MOD(ps.ps_id, 2) = 0;
```

## 수정 이유
- 기존 재고 관련 데이터는 `ProductStock 100건`, `PhysicalInventory 8건`, `ProductStockLog 200건` 수준이라 조회 성능 차이를 체감하기 어려웠다.
- 기존 재고 데이터를 기반으로 대량 복제해 재고 목록, 실사 목록, 이력 조회에서 충분한 부하가 걸리도록 조정했다.
- FK를 유지한 상태로 삽입해 애플리케이션 조회 로직이 그대로 동작하도록 했다.
